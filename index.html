UES Website Work Log

A plain-language record of the work done on universalenvironmentalservices.com.

Prepared by Manny Pachano for Juan Fritschy and Lisa Sandefur.

Last updated: August 9, 2026

What this page is. Each row below is a problem we found and what we did about it. It is written for people who do not work with websites.

Traffic and ranking figures are not on this page. Those are covered in the monthly reports.

1Problems solved

Most of these are normal for a site that ran for years without a technical check. None were caused by recent activity. Where a change was made to the live site, it was tested before and after.

The problemWhat we did about itWhen
The footer still read 2017 to 2022 Changed it to 2026. It now updates itself every year. August 3
The site loaded under four different web addresses, and search engines could not tell which one was correct Set one address as the correct one. The other three now send visitors and Google to it automatically. August 3 and 4
A full copy of the site was public at a second address That address now sends visitors and Google to the real site instead. August 4
The site's automatic task scheduler had stopped, so backups and updates were stuck Set it to run every five minutes. Scheduled jobs work again. August 4
Nothing was saved in visitors' browsers, so every repeat visit downloaded the whole site again Set images and design files to save in the browser. Repeat visits load faster. August 4
Sixteen plugins were out of date All sixteen are now updated. August 5
Two pages had messy web addresses ending in -2 Gave the Georgia and antifreeze pages clean addresses. The old addresses send visitors and Google to the new ones. August 5
Two copies of the West Virginia page were competing with each other on Google Kept the better copy at one clean address. The other copy now sends visitors there. August 5
The site's design software was six years out of date Updated it from its 2020 version to the current version. Registered its license, so future updates arrive on their own. August 6
Google was reading an outdated table of contents for the site Cleared the site's saved copies. Google now reads the current one, with the new page addresses. August 6
The server's system software was out of date, and the server itself was too small for the site Moved the site to a larger server with current software. One move fixed both problems. Visitors saw no interruption. The site's security certificate now renews itself. August 7
Google's records pointed at an outdated version of the site's page list (sitemap) Submitted the current version. August 7
Two speed plugins did overlapping work, and one had been giving Google outdated information Removed that plugin. The server now handles the speed work itself. The plugin we kept only does database cleanup. Google now always reads current information. August 7
Automated programs were constantly hitting a technical entry point of the site, wasting server power Closed that entry point to everyone except one approved service. Those requests are now rejected before they use server power. August 7
Over 400 links inside the site still pointed at the www and non-secure (http) versions of our web address Repointed them to the correct secure address. Those pages now load right away, whereas before they had to be redirected which slowed down the site. August 9
Missouri had two separate pages competing with each other on Google Merged them into one page at a single address. The old address sends visitors and Google to it. August 9
